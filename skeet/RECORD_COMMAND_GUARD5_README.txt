Record Command Guard 5 — нативная правка GameSense

В архиве: skeet.dll, соответствующий injector.exe, исходники проекта,
проверки и отчёты. Lua для этой правки не требуется.

Что изменено

Перед добавлением автовыстрела проверяется та же формула исторического тика,
которую оригинальный код использует позднее для command.tick_count:
выбранный тик + округлённая интерполяция, с исходным ограничением команды.
Если положительный исторический тик не проходит это ограничение, новая
ветка не добавляет автовыстрел по несогласованной записи. Оригинальная
поздняя финализация в таком случае оставляет прежний command tick.

Защита не заменяет матрицы, не экстраполирует противника, не расширяет
серверное окно бектрека, не меняет spread/hitchance/резольвер. Уже имеющиеся
биты ручного IN_ATTACK/IN_ATTACK2 не снимаются. Варианты без положительного
исторического тика сохраняют прежний путь. Дополнительная проверка запускается
один раз перед потенциальным автовыстрелом; трассировок мира в ней нет.

Это конкретная защита согласованности команды, а не доказанное устранение
всех промахов correction или prediction error. Срабатывание найденной
ветки на пользовательском сервере ещё не подтверждено. Игровой хитрейт
и FPS здесь не измерялись: CS:GO и процесс пользователя недоступны.

Запуск

1. Полностью закрыть прежнюю CS:GO: замена DLL на диске не убирает старые
   хуки из уже запущенного процесса.
2. Распаковать архив целиком, оставив injector.exe рядом со skeet.dll.
3. Запустить legacy CS:GO x86 и injector.exe. Сборка не предназначена для CS2.
4. Версия в окне загрузчика: Record Command Guard 5.
Защита включается внутри DLL; кнопка в Lua ей не нужна.

Основа — Aim Recovery 4. Старые экспериментальные Consistent pose,
Extrapolation и Hitscan по-прежнему не устанавливаются. Их отключённые
контролы во вкладке Improved не означают, что новая защита не работает.
Математика movement и его прежний способ подключения не изменялись.

Диагностика

DLL экспортирует skeet_record_guard_status (5 полей по 32 бита):
version=1, size=20, installed, considered, rejected.
installed становится 1 после установки; considered считает потенциальные
автовыстрелы, rejected — отказы новой проверки. Это счётчики, не хитрейт.
Если сигнатуры исходного участка изменены, загрузчик отказывает в запуске
этой сборки вместо записи патча по неподходящему адресу.

Проверки

- 1216 проверок состояния процессора и переходов emitted x86-кода.
- 1152 сравнения с исполнением исходной финализации тика (64/128 tickrate).
- 18 случаев установки/ошибок/отката с контролируемыми WinAPI.
- Отдельные отрицательные проверки неизвестных байтов и некорректных входов.
- Сборка Windows x86; исходный embedded core сохранён без изменения ресурса.
- Повторные проверки существующих movement-экспортов: 300 + 18 случаев.
Это изолированные проверки, не запуск DLL entry/injector в игре.

Сборка исходников

Python + requirements-build.txt; для проверок — requirements-test.txt и g++.
  python build_windows.py
  python build_guard_tests.py
  python tests/validate_shot_guard.py
  python tests/validate_shot_guard_install.py
  python verify_source.py
  python tests/verify_recovery_boundary.py

Исходники включают загрузчик/обёртку и исходный бинарный core известной
версии; они не являются полностью восстановленным C++-кодом GameSense.
Основная правка: source/skeet/shot_guard_plan.h и shot_guard_runtime.h;
подключение после VM fixups в source/skeet/skeet.cpp.
Для отката доступен прежний архив Aim Recovery 4 в том же репозитории.
