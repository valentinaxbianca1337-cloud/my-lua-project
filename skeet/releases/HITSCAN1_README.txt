Improved Hitscan 1 + NL Movement

Improved -> Hitscan (четвёртая панель)
Ползунок Units стоит слева от checkbox Hitscan. В узком меню checkbox
переносится на следующую строку, чтобы подписи не пересекались.
После включения видна одна короткая подпись: May reduce FPS.

Значения ползунка
GS — штатный набор точек Skeet, без добавлений.
NL — дополнительные точки по адаптированному generic capsule шаблону
     Neverlose. Сохраняются исходные точки GS, добавляются отсутствующие
     боковые точки и верхняя для hitbox6; это не полный ragebot Neverlose.
10..112 — свой бюджет дополнительных точек на текущую позу цели.
     Исходные точки сохраняются, общий предел остаётся 112.
     Повышение бюджета не означает, что на каждом проходе будет ровно столько
     точек: нужны подходящие выбранные капсулы и свободное место в буфере.
Units здесь означает бюджет точек, а не расстояние в мировых координатах.
GS/NL являются режимами, а не выдуманными универсальными числовыми эквивалентами.

По умолчанию Hitscan выключен, выбран GS. При выключении/в GS обработка списка
точек не меняется. Максимум 112 подтверждён двумя native inline buffers:
input112*24 bytes, evaluated112*56 bytes. Размеры буферов не увеличиваются.

Что меняется
Новый модуль дополняет кандидатные точки перед штатной оценкой урона.
Все исходные точки, порядок и private metadata сохраняются. Выбранные хитбоксы
и multipoint mask учитываются; добавления ограничены подходящими капсулами
с уже имеющимися native multipoint samples. Боксы и остальные неподходящие
случаи обрабатываются как прежде. Размер хитбоксов, разрешённое время записей,
порог урона, hitchance и resolver модуль не увеличивает и не отключает.
Больше проверок может снизить FPS; рост hit rate не гарантирован.

Предел переноса NL
Проверен point-pattern kernel41490FA0 из предоставленного nl.image.bin.
335 примеров сравнения с его инструкциями; max coordinate difference около
0.000008 при заданной scale и независимой модели capsule clipping.
Клиентский clip helper NL с адресом289A6D60 отсутствует в материалах: на
стенде заменён независимым bisection oracle, в модуле — analytic intersection.
Weapon/spread auto-scale NL не переносился: сохраняется консервативная scale,
выведенная из уже построенных точек Skeet (максимум0.95). Это адаптация
расположения дополнительных точек, а не полный hitscan Neverlose1:1.

Установка
Полностью перезапустить игру. Использовать skeet.dll и injector.exe из этого
комплекта; Launch_Improved.cmd сохраняет прежнюю UI диагностику.
Панели Backtrack / Lag records / Extrapolation сохранены; их алгоритмы и
прежний movement/Lua побайтово сохранены из UI2. Для movement отдельно нужен
nl_movement_combined.lua. Старые Lua правки сканирования для первого сравнения
оставить выключенными, как в предыдущем тесте.

Проверки и исходники
source_project содержит исходники и тесты. python build_windows.py собирает
Windows x86 с ziglang0.13.0. python build_tests.py собирает закрытые fixtures.
python tests/validate_hitscan_native.py
python tests/validate_improved_native.py
python tests/validate_improved_frame.py
python tests/validate_hitscan_value_text.py
python tests/compare_nl_hitscan.py /path/to/nl.image.bin
build/test_hitscan_points — переносимые проверки, исходные точки и canaries.

Отчёты в reports/. Исторические отчёты прежних версий — baseline_ui2/.
Стек/GPR/XMM/x87/MXCSR и разные адреса размещения проверяются на машинном коде;
исходный GS цикл читает добавленные кандидаты. Damage traces/HC evaluation,
DLL entry, настоящий injector и игра здесь не запускаются. Практический
эффект и FPS нового режима на сервере ещё не измерены.
