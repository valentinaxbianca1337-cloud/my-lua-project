GameSense Performance Audit 1

Это измерительный комплект, не FPS-патч. DLL, movement, настройки аимбота,
память процесса и cvars он не изменяет. Проверяемые места могут быть на любой
карте. Полный исходник защищённого ядра Skeet этим исследованием не восстановлен.

Быстрая проверка
1. Загрузить performance_audit.lua. Элементы появятся в LUA -> B.
2. Воспроизвести плохую сцену: одна и та же позиция, камера, оружие, противник.
   Удобнее локальный сервер с неподвижным ботом. Сначала обычные настройки.
3. В Sample label написать bad_rage_on_NL. Нажать Start performance sample,
   закрыть меню, 2 секунды не считаются. Следующие 10 секунд не менять сцену.
4. Полностью снять именно checkbox RAGE -> Aimbot -> Enabled. Повторить замер
   с меткой bad_rage_off. Один лишь отпуск hotkey может быть недостаточным
   для полного выключения; реальное состояние checkbox/hotkey сохраняется.
5. Включить Rage обратно, повторить bad_rage_on_repeat. Порядок A-B-A помогает
   заметить дрейф сцены/нагрев/фоновые события.
6. Если выключение Rage помогает: оставить Rage включённым и выключить только
   Improved -> Hitscan. Замер bad_hitscan_off. Затем выключать по одной опции:
   Consistent pose, старые Lua native fixes. Не отключать всё одновременно.
7. Для оценки чистого ядра повторить с остальными Lua выгруженными, кроме
   performance_audit.lua. По возможности сравнить ту же сцену в исходной сборке.
8. Повторить good_rage_on в месте без просадки на той же карте.

Все результаты пишутся в csgo/performance_audit.json. Достаточно прислать этот
файл и точку воспроизведения. Если нужен разбор конкретной причины в ядре,
нужна и CPU-трасса ниже. Поля с отсутствующими references будут пустыми;
скрипт не придумывает состояния недоступных нативных опций Improved.

Скрипт ничего не переключает сам. После ручного сравнения вернуть настройки
самостоятельно. Открытие меню, смена карты, изменение Rage checkbox/hotkey во
время сбора помечают замер невалидным. Изменение прочих настроек и движение
не отслеживаются непрерывно; снимки начала/конца помогают проверить условия.
Сохраняется не больше 24 последних замеров в рамках загрузки Lua. Существующий
JSON от прошлой загрузки заменяется при сохранении; перед новой сессией
сохранить предыдущий файл отдельно, если он нужен.

Что означает результат
frames — интервалы между paint_ui по client.timestamp, в миллисекундах.
engine_absolute_frames — globals.absoluteframetime, если API доступен.
FPS = 1000 / среднее время кадра; это не среднее отдельных мгновенных FPS.
Есть median, p95, p99, максимум, число кадров дольше 16.667 и 33.333 мс.
Затраты самого callback записаны отдельно, без записи файла и сортировки.
Сам колбэк измеряет только своё тело, без стоимости диспетчеризации событий Lua;
для сравнения оставлять этот измеритель загруженным во всех вариантах.
Обработчики setup_command/run_command/net_update_end/aim_fire только считают
события. Имена игроков, SteamID и адрес сервера не собираются.

Если Rage off возвращает FPS, это локализует связанную с Rage работу, но ещё
не доказывает autowall: при выключении Rage могут иначе работать зависимые Lua.
Если Hitscan off заметно помогает, дополнительные точки увеличивают затраты
в этой сцене. Это не доказывает, что штатный GameSense имеет ту же причину.
Если Rage off не помогает, исследовать отрисовку/ESP/Lua/движение/другие CPU
задачи. Сравнение разрешения полезно для проверки GPU-нагрузки, однако само
по себе не доказывает конкретный GPU bottleneck; нужен профиль/телеметрия GPU.

CPU-трасса Windows (без внедрения новых hooks)
Запустить Capture_CPU.cmd от администратора. Нужен штатный Windows wpr.exe.
После старта вернуться в игру и удерживать сцену. Через 15 секунд запись
сохранится рядом с cmd в cpu_profile.etl. Первые/последние секунды переключения
окон при анализе исключить. Для второго места сначала переименовать ETL:
например, bad_rage_on.etl и good_rage_on.etl. Если другая WPR запись уже идёт,
скрипт не отменяет её. Запись использует отдельное имя SkeetPerfAudit.
При ошибке сохранения проверить wpr -status -instancename SkeetPerfAudit.
Если закрыли cmd до конца, сохранить оставшуюся запись вручную:
wpr -stop recovered.etl -instancename SkeetPerfAudit

ETL содержит системную диагностику процессов. Не публиковать его в открытом
репозитории; передать приватным вложением. Запись ETW создаёт собственные
затраты, поэтому FPS сравнивать отдельными Lua замерами без WPR, а ETL
использовать для локализации CPU-времени. Для просмотра подходит Windows
Performance Analyzer: CPU Usage (Sampled), процесс csgo.exe, Stack. При блокировке
потока/ожидании потребуется также анализ ожиданий, не только CPU samples.

Реверс конкретного ядра 8802
static_evidence.json описывает только локальный участок. В исходном ядре
цикл 0x4335EF62..0x43360708 обрабатывает каждую кандидатную точку. Вложенные
циклы и вызовы найдены; исходный код всех вызываемых функций не восстановлен.
points <=112 — вместимость буфера, не измеренное число проверок в секунду.
Это объясняет, почему дополнительные точки могут увеличить работу, но не
измеряет стоимость геометрии конкретного места. Полный профиль на пользовательском
ПК ещё не снят, прирост FPS и причина просадки не установлены.

Если профиль подтвердит конкретный повторный расчёт, оптимизировать нужно
именно его: убрать доказанную повторную работу в неизменном контексте или
исправить обход геометрии. Кэш autowall между разными tick/позициями/оружием/
позами может давать устаревший урон. Снижение точек и пропуск записей — обмен
полноты поиска на скорость, его нельзя выдавать за точное ускорение без потерь.

Проверки измерителя
Требуется Python + lupa==2.8 (LuaJIT 2.1 runtime).
Запуск: python tests/test_recorder.py
18 проверок: статистика/пустые и нулевые данные, запись 200FPS, остановка при
смене карты/меню/Rage, недостаток кадров, часы назад, отключение Lua, отсутствующие
references, hotkey с несколькими возвращаемыми значениями, ошибка записи файла.
Это контролируемые API-границы, не запуск Lua в настоящей игре или WPR в Windows.
