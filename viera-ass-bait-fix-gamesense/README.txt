VIERA ASS BAIT FIX — GameSense CS:GO, редакция 1.0

Файл: Viera_AssBaitFix_gamesense.lua
Это самостоятельная Lua, можно загрузить вместе с Gazolina.
Меню: AA -> Other -> Ass bait fix. Correction limit: 1..58°, default 58°.
При первом создании чекбокс выключен. Настройки хранятся штатным GS-конфигом.
Библиотеки, Neverlose, FFI, сигнатуры и сетевые загрузки не нужны.

СУТЬ И ПРЕДЕЛЫ ПЕРЕНОСА

Это разрешённая пользователем адаптация идеи через публичный API GameSense,
а не полный перенос матриц/lag records из Neverlose. Оригинал работает с
закрытыми структурами Neverlose: lag_ringbuf_t, lag_record_t, desync_weight,
abs_yaw, matrix_center, matrix_left, matrix_right. Публичные entity/plist API
GameSense не предоставляют соответствующего доступа. Значения сетевых props
не равны внутреннему abs_yaw/desync_weight resolver'а Neverlose.

Новая Lua использует историю сетевых eye yaw и lower-body yaw противника и
временно задаёт Force body yaw через plist. Это эвристика; она может выбрать
неверную сторону. Улучшение попаданий не гарантируется и здесь не проверялось
в настоящем клиенте. Запись/подмена матриц, bone cache и backtrack records
не производится, обработка прошлых записей Neverlose не воспроизводится.

ФИЛЬТР И КОРРЕКЦИЯ

1. Локальный игрок должен быть живым участником T или CT.
2. Обрабатываются только живые, не dormant противники. Ограничения target team==2
   из исходника нет: работает против T при игре за CT и против CT при игре за T.
   Союзники не затрагиваются.
3. Текущий duck amount должен быть >=0.8, скорость по горизонтали в квадрате <=90.
   ВАЖНО: в оригинале сравнивается vx²+vy² с 90, что соответствует примерно
   9.49 units/s, а не скорости 90 units/s. Этот порог сохранён.
4. Хранятся до 8 уникальных сетевых samples по m_flSimulationTime. Повторные
   вызовы с тем же simulation time не добавляют историю. Нужны минимум 3 sample.
5. Jitter проверяется по нормализованным изменениям сетевого eye yaw: если
   большинство переходов превышает 18°, коррекция пропускается.
6. delta = normalize(lower-body yaw - eye yaw). Три последних sample должны
   иметь |delta|>=3° и одинаковый знак. Значение Force body yaw равно
   +Correction limit либо -Correction limit по этому знаку.
   Это доступная публичная оценка, не прямое измерение скрытого desync.
7. Если данных нет, противник встал/двигается/dormant/умер, данные не обновлялись
   больше 0.5 с или simulation time откатился, коррекция снимается. После разрыва
   истории вновь нужны три подходящих сетевых обновления.

PLAYER LIST И ВОССТАНОВЛЕНИЕ

Уже включённый вручную Force body yaw Lua не перезаписывает.
При собственной активации сохраняет прежние флаг и числовое значение.
Пока запись принадлежит этой Lua, они возвращаются при прекращении условий,
выключении чекбокса, смерти, новом раунде, карте, disconnect, загрузке/сохранении
GS-конфига и выгрузке скрипта. При ошибке API функция выключается и пытается
вернуть захваченные значения; пояснение выводится с префиксом [Ass bait fix].

Если во время действия пользователь/другая Lua изменили Force body yaw,
новая правка сохраняется: скрипт прекращает владение этим противником до
сброса/повторного включения функции. Смена identity в том же entity slot не
переносит владение на нового игрока. Используется Steam ID, для ботов — имя;
полной гарантии различения ботов с одинаковыми именами публичные данные не дают.

ОШИБКИ В ПРЕДОСТАВЛЕННОМ NEVERLOSE-ИСТОЧНИКЕ

В detect_jitter переменная avg_delta инициализируется нулём и не меняется;
финальное avg_delta*0.5<30 всегда true. Поэтому при >=3 записях этот детектор
всегда считает цель jitter и пропускает коррекцию. Новая Lua считает переходы
в ограниченном окне и не копирует эту ошибку.
В блоке коррекции также есть обращение к anim.matrix_left/right, хотя anim
в этой Lua не объявлен; результат sel_m дальше не используется. Этот код
не перенесён. Ограничение только на T-цели также удалено.

ПРОВЕРКА

Компиляция и запуск на модели API: настоящий LuaJIT 2.1 / Lua 5.1 через lupa.
20 сценариев пройдены: T/CT, уникальные сетевые samples, crouch/скорость,
порог vx²+vy², jitter/wrap-around, знак и предел коррекции, ручные настройки,
внешние изменения, stale/rollback, dormant/смерть/союзник, смена identity,
выключение, раунд/карта/конфиг/выгрузка, события смерти/disconnect,
неподдерживаемые plist-поля, rollback при ошибке записи, ограниченная история
и отсутствие повторных записей одинакового значения.
Самого GameSense/CS:GO здесь нет; запуск в настоящем клиенте и точность
эвристики в игре не проверены.
