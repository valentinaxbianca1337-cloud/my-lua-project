nyameeow.pink — Builder audit 2

Проверен путь настроек: меню -> состояния T/CT -> CFG -> setup_command ->
состояние L/R/инвертера -> ui.set нативных Pitch/Yaw/Body yaw.

Подтверждённые ошибки, исправленные в этой версии

1. Static + Delay: ранний return в update_lr игнорировал включённую задержку.
   Теперь Delay переключает L/R yaw, при этом Static Body yaw остаётся
   постоянным, как и требует выбранный режим.
2. Первая команда после создания фазы не запоминалась. Её повторная обработка
   могла сразу израсходовать шаг Delay. Повтор той же команды теперь ничего
   не продвигает, в том числе в Sequential, Random и Smart Random.
3. Идентификатор фазы не содержал Team/State. Состояния с одинаковыми
   настройками задержки могли наследовать counter/freeze_until/disable_until.
   Теперь состояния разделены по команде и фактически выбранному профилю.
4. При отрицательном управляемом Jitter переключение Defensive -> Desync
   использовало знак фазы, а не знак записываемого Body yaw. Исправлено.
   Отдельно учтён Static с независимой фазой L/R yaw и инвертер.
5. При нативном Freestanding body yaw запрошенный offset больше не выдаётся
   за автоматически выбранную сторону. Для этого пути остаётся наблюдение
   клиентского pose, с ограничениями такого наблюдения.
6. Дополнительно защищены raw legacy yaw-поля от NaN/Infinity до modulo/RNG.

Проверка чисел и знаков

Custom pitch: -89..89; yaw: нормализуется в -180..180.
Jitter value: -58..58; отрицательный value переворачивает знак самого
запрашиваемого jitter-offset, а не становится ещё одним увеличением угла.
L/R: величины 0..58, выбранная сторона получает знак; инвертер переключает
сторону один раз. Рандомизация величины ограничена 0..58. Повтор одной
команды не генерирует новую случайную величину.
Static: фиксированный запрошенный offset +58/-58 по направлению и инвертеру.
Поле Jitter value в режиме Static не является регулятором силы; оно скрыто
в этом режиме. Это сохранённая схема меню, а не подтверждение физического
десинка величиной 58 градусов.

Что означает число 58

Текущая Lua записывает это число в нативный Body yaw offset. Она не измеряет
и не калибрует равенство этого числа фактической разнице eye/feet yaw на
сервере. Поэтому утверждать «ползунок 58 гарантирует реальный десинк 58»
для этой реализации нельзя. Отдельного управления Fake yaw limit в ней нет.
Величина реального десинка зависит от нативной логики, скорости, приседания,
анимации и сторонних изменений параметров. Произвольный множитель градусов
для неизвестной нативной реализации не добавлялся.

Имеющийся C++-проект содержит загрузчик и бинарный core, а не полностью
восстановленный исходник anti-aim. Проверка Lua, API-вызовов и моделей UI
не выдаётся за проверку серверной анимации или полный реверс native anti-aim.

Задержки

Основная фаза Delay продвигается на командах chokedcommands == 0.
При choke она удерживается. Поэтому текущая метка t не является гарантией
длительности в серверных тиках при включённом fakelag. Таймеры Freeze и
Disabling используют globals.tickcount. Смысл этих старых единиц сохранён;
произвольного изменения сетевого тайминга в этой версии нет.

Проверки

- 4032 сочетания режима, знака, величины, инвертера, L/R и задержек.
- Все 22 маршрута Team/State через настоящий setup_command модуля Lua.
- Sequential, Smart Random, Random, Freeze, Disabling и повтор команд.
- Отдельное воспроизведение четырёх ошибок предыдущей версии.

- Компиляция полного файла LuaJIT; PNG-ресурсы не менялись.

не выполнялись. Иконка из сообщения по-прежнему ожидает отдельный PNG/WebP.
