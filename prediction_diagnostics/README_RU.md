# Диагностика предсказания и промахов

В опубликованной сборке `skeet-windows-x86-overlay-v1.zip` новый предиктор **не подключён к Rage**. Она содержит фикс загрузки/Steam Overlay и оригинальное бинарное ядро. Поэтому улучшение предсказания от этой сборки не ожидалось.

Этот Lua собирает данные для разбора конкретных промахов. Он не меняет прицеливание, entity properties, команды, cvars или DLL, не устанавливает хуки и не отправляет данные по сети.

## Как записать

1. Скачать [архив диагностики](https://github.com/valentinaxbianca1337-cloud/my-lua-project/raw/refs/heads/main/downloads/skeet-prediction-diagnostics-v1.zip).
2. Положить `capture.lua` в папку Lua-скриптов GameSense и загрузить его через меню Lua.
3. В разделе `LUA → B` включить **Record prediction diagnostics**.
4. Воспроизвести 2–3 характерных промаха и сразу нажать **Export prediction trace**. Затем выключить запись.
5. Прислать файл **`skeet_prediction_trace.json`**, который создаст API `writefile` в доступном ему каталоге игры. Экспорт проверяется обратным чтением; в консоли GameSense появится сообщение об успехе или ошибке. Если файл не виден, найти его по имени в папке игры.

При повторном включении записи начинается новое окно наблюдений. Буфер ограничен 8192 записями сущностей и 512 событиями; старые данные вытесняются. Поэтому экспортировать нужно сразу после воспроизведения. Выгрузка скрипта удаляет ещё не экспортированные наблюдения.

Названия игроков, Steam ID, IP и чат не записываются. Сохраняются индексы целей, координаты/скорости, временные метки и данные событий выстрелов. Файл записывается только по кнопке экспорта.

## Что можно проверить

- Задержки получения новых simulation-time записей, повторные/регрессирующие timestamps и переходы dormant/dead.
- Флаги `interpolated`, `extrapolated`, `teleported`, `boosted`, `high_priority`, если текущая Lua API передаёт их в `aim_fire`.
- Значения `hit_chance`, `backtrack`, `tick`, координаты выбранной точки и причины `aim_miss` в исходном виде, без догадок о единицах необязательных полей.
- Связь каждого `aim_hit/aim_miss` с событием `aim_fire`, возраст последней полученной записи на момент выстрела.
- `cl_interp`, `cl_interp_ratio`, `cl_updaterate`, серверные ограничения и сообщаемую клиентом latency.

Отсутствующий флаг отличается от `false`. Причина промаха берётся из host API и сама по себе не является независимо доказанным диагнозом. Координаты прицеливания не сравниваются с origin как будто это одна и та же точка: origin не является центром выбранного хитбокса.

## Для 64 tick и пинга около 100 мс

Один тик занимает 15,625 мс. 100 мс соответствуют 6,4 таким интервалам, но это **не готовое упреждение**: значение пинга может включать время туда-обратно, а выбранная запись/лагкомпенсация уже учитывают часть задержки. Автоматическое прибавление 100 мс к simulation time может дважды учесть задержку.

`receive_time` берётся из `globals.realtime`, а `simulation_time` — из сущности. Это разные шкалы, их абсолютные значения не вычитаются друг из друга. `reported_latency` сохраняет смысл `client.latency` текущего хоста; деление на тики служит только описанию измерения. Не делаются выводы о полном RTT или one-way latency без данных конкретного клиента.

Оценка lerp по cvars учитывает доступные ограничения rate/ratio, но не считается доказательством времени, которое выбрал Rage. Скрипт не предлагает наугад менять interp или упреждение.

## Локальный разбор

Для сводки достаточно Python 3.10+ без дополнительных библиотек:

```sh
python analyze_trace.py skeet_prediction_trace.json --output trace.analysis.json
```

Сводка выводит статистику времён, флагов и причин промахов. Она не заявляет улучшение попаданий и не доказывает подключение экспериментального C++ предиктора: публичная Lua API не раскрывает эту связь.

## Проверки

`tests/test_capture.lua` исполняет настоящий `capture.lua` в LuaJIT с контролируемыми заглушками GameSense API: opt-in, нулевые координаты, сохранение `false`/отсутствующих полей, корреляция выстрелов, dormant/spawn, NaN, регрессия simulation time, переполнение обоих буферов, отключённая запись и ошибка файлового экспорта. Запрещённые функции изменения игры заменены заглушками, вызывающими ошибку.

`tests/test_analyze.py` проверяет раздельные часы, 64 tick / 100 мс, серверные ограничения lerp, потерянные события и валидацию входных данных.

```sh
luajit tests/test_capture.lua capture.lua
python -m unittest discover -s tests -p 'test_*.py' -v
```

Эти проверки используют искусственные данные. Настоящая GameSense Lua API и игровой процесс в этой среде не запускались. Если загрузка Lua завершится ошибкой API, нужен текст ошибки из консоли.
